# 手动策略与局部识别

## 打法与兼容性

GUI 开跑前选择打法，CLI 使用 `--strategy`，TOML 使用 `[battle].strategy`。

| 标识 | 行为 |
| --- | --- |
| `two_edge` | 活动兵优先，其余普通兵按兵栏顺序；每种兵平分两边，奇数余数在第一边。不下英雄。无活动兵仍可运行。 |
| `edrag_line` | 所有普通兵按兵栏从左到右，沿第一条边均匀投放；之后英雄按兵栏顺序从该边中点跟进。不识别或强制优先下雷龙。 |
| `verified` | 保留原资源筛选和部署流程；缺少配置字段时仍是原默认值。 |

两种线形打法共用最小缩放验证，选兵显示当前红色禁放边界后，用线段检测取得两个西侧边，并向外偏移 32 个基准像素；不再假定缩到最小即可使用固定屏幕落点。不使用法术/攻城器、不主动开英雄技能。投放不确定只补观察，不补点；保留已确认的数量与失败信息，发出过投兵动作后仍尝试等待结算、回村。失败或部分投放不会被记成全部成功。英雄必须验证选中状态与投放后的血条，不要求技能使用。

边界检测使用 HSV 两端红色范围、形态学顶帽筛选细线和 Hough 线段，检查方向、像素支持率及两边交点。默认允许 1 像素偏差，不能同时确定两边时才尝试 2 像素偏差；看不清则停止部署。必须先看到兵卡的闭合白色选中框，再信任红线。选中边框导致完整识别漏卡时，用当前帧头像匹配及数量读取重新核对每张原有普通兵卡，不直接沿用旧数量。回村资源数字动画引起宝石差异时，最多补读三帧；持续差异或仍不能确认会报失败。

## 新增策略接口

`src/autococ/strategies.py` 提供 `BattleStrategy.build_plan(BattleContext) -> DeploymentPlan`。输入是已核验的普通兵、英雄和当前边界外侧的部署线；输出是依序执行的普通兵与英雄 `Placement`，各项包含兵卡与落点。

新策略实现该接口并加入 `STRATEGIES` 注册表；配置校验、CLI、GUI 自动共用该注册表。当前接口覆盖固定视角普通兵铺线及英雄跟进，新增法术时需明确扩展执行器和核验规则。策略内不要截图或点击；执行器共用数量核验、超时、停止及部分失败回执。

## 识别路径

- `GameSession.observe(..., purpose="full" | "troop_count" | "hero" | "settlement", slot=...)` 明确本次所需信息；默认行为兼容原调用。
- 完整观察提供场景、军队清单和兵栏。两个稳定 HUD 锚点从已识别帧采样；以后只在当前位置匹配，绝对亮度差用于拒绝弹窗压暗。另检查云层及中央大块灰色弹窗。
- 部队核验先在当前卡附近匹配头像内部，允许选卡缩放，重新计算数量区域；单行 OCR 直接接收内存图像，灰卡读不清时二值化重读。仍不确定就整帧重新识别。
- 快速观察只返回当前帧实际读取的字段，不复制旧兵数、资源或按钮。场景切换会回退完整识别；等待结算通常只检查锚点，发现变化后完整读取结算。
- 图片缓存只保留两帧，模板/缩放缓存有上限；路径、修改时间和大小参与失效判断。缓存不会把上次截图当成本次截图。

识别日志包含 `recognition_scope`、`fast_fallback`、`recognition_timings_sec`，截图耗时独立记录。固定界面布局之外的变化可能增加完整识别回退次数。

## 方案比较

| 方案 | 适用范围与局限 | 此次选择 |
| --- | --- | --- |
| 预存整张截图对照 | 地图、兵数、计时、动画会不断改变；整图差异无法直接回答哪张兵卡还剩多少 | 不作为主识别 |
| 小区域模板匹配 | 固定 HUD、按钮和兵卡头像合适；需避开数字、选中框及动画，匹配失败要回退 | 用于场景守卫、头像定位；模板在内存中缓存 |
| 局部单行 OCR | 读取当前数量，覆盖不同数字；图像不清时会慢或拒识 | 部队数量主路径，失败时完整识别 |
| 数字字形模板 | 本机原型约 1–3 毫秒，但目前只有 0、1、x，灰零仍拒识，其他数字未经验证 | 保留实验脚本，暂不接入执行 |
| 单独训练分类/检测模型 | 需要覆盖不同皮肤、灰卡、选卡缩放及分辨率的标注样本和验收集 | 当前数据不足，先不新增模型依赖 |

现有代码原先已有模板匹配，但每次观察仍跑完整 OCR、兵栏和场景分析。此次主要收益来自明确每次需要的信息，减少重复整图识别和解码；并非只换成“存截图比对”。完整路径仍承担初始识别和不确定情况的重新确认。

## 数字模板实验与复现

数字模板原型只在 `scripts/benchmark_digits.py` 中，**未接入生产识别**。从历史截图提取 0、1、x，在不同截图上测试；5 张测试图中 3 张正确、2 张拒识、0 张错误接受。正常卡片上的结果好，但灰零和其他数字覆盖不足，因此保留局部 OCR。不同帧可能仍有相同字形，这不是跨版本泛化验证。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

离线回放不连接设备。输出在 `reports/recognition-replay.json` 与 `reports/digit-template-experiment.json`；完整路径和快速路径各自重新解码待测截图，分开记录首次运行、热运行中位数/P95、回退次数及与旧回执数量的一致性。历史截图未随代码全部入库，需要本机已有对应运行目录。

本机此次回放共 12 张图、3 轮，36 次新旧场景/数量对比均一致。热运行部队核验中位数从 2.497 秒降至 0.184 秒（约降低 92.6%）；快速路径 P95 为 2.287 秒，包含侦察转开战的完整识别回退。热运行全部样本回退 4/24，分别为开战和结算转换。该指标包含图片解码，不包含实时截图，且只代表这组离线样本。
