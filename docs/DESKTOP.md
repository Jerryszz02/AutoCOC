# AutoCOC 桌面界面

更新日期：2026-09-26。桌面界面使用 Python/Tk，与 CLI 共用日常任务定义、停止信号和报告。完整游戏验收仍按 [ACCEPTANCE.md](ACCEPTANCE.md) 执行；新版目标功能尚无连续 10 场或 60 分钟实机证据。

## 打开与操作

在项目目录双击 [启动AutoCOC.cmd](../启动AutoCOC.cmd)，或运行：

```powershell
.\.venv\Scripts\python.exe -m autococ.gui --config config.toml
# 相同界面的 CLI 入口：
.\.venv\Scripts\python.exe -m autococ.cli gui --config config.toml
```

界面使用 Python 标准库 Tk，不需要浏览器、Web 服务或额外界面包。重新安装本项目后也可使用 `autococ-gui` 入口；已有虚拟环境直接运行以上命令即可。

1. 在「运行」页勾选本次任务：收集资源、请求增援、部落捐兵、刷资源、刷活动、部落竞赛。选中任务后可上移/下移；三个对战任务可以同时勾选，按清单顺序执行。连接、检查军队、结算与回村是内部步骤。
2. 点任务旁「设置」会切到「配置」页并定位它。三种对战分别保存打法、每场搜索上限、最多战斗场数、最长运行时间及资源筛选。刷资源可填写库存目标或勾选金币/圣水/黑油满仓；刷活动和部落竞赛填写实际进度适配 TOML 与目标。活动得分条件在适配文件中声明；竞赛只运行已接受的任务。
3. 配置页上方设置设备地址、运行模式和回村维护间隔。默认「离线预演」只生成任务计划与 `simulated` 报告，不连接模拟器、不操作游戏。需要现场执行时才手动切换为「实机执行」；每次重新打开仍默认预演，也不会自动开始。
4. 运行页右侧区分**完成战斗、游戏胜利、目标达成**，显示当前场数/阶段、村庄库存、已核验累计战斗收益和实际活动/竞赛进度。无法读取的值显示「未知」。最近记录、详细日志、历史报告及截图证据均可在运行页查看。
5. 「停止」发送协作式取消。已发出的单次调用等待其自身超时/返回，之后不再发出新输入；关闭正在运行的窗口也先请求停止并等报告保存。任务、打法或适配文件不合法时会在连接设备前提示。

「保存配置」写到所选配置同目录的 `<配置文件名>.desktop.json`，例如 `config.desktop.json`，用临时文件加替换写入。基础 `config.toml` 不会被改写，实机模式不会被持久恢复。设备、报告、截图、模板和打法/适配的相对路径以基础配置文件所在目录解析。任务 TOML、活动适配 schema 和命令行用法见[日常助手说明](DAILY_ASSISTANT.md)。

任务在一个后台线程中运行，重复开始会被拒绝。历史页展示最近 100 份报告，选中后可阅读结果、打开 Markdown 以及检查原始截图；完整后台日志写入 `reports/desktop-*.log`。本机的[运行页截图](../reports/gui-daily/run-150dpi.png)、[配置页截图](../reports/gui-daily/configuration-clan-games-150dpi.png)和 `reports/gui-daily/manifest.json` 位于 Git 忽略目录，仅是界面检查记录，不是实机验收证据。

## 捐兵代码的实际边界

已有“扫描聊天 → 打开明确的捐赠请求 → 观察捐兵窗口 → 逐个单位执行并核验”的代码路径，以及逐单位执行、延迟重拍、不重复点击、部分收据保留和支出核验逻辑。

**生产识别器目前尚不生成 `donation_view`，真实捐兵仍未实现完整可用流程。** 当前真实运行找到请求后最多打开窗口保存证据，无法核验捐兵交互时给出 `donation_interaction_not_supported`；日常助手将此类任务显示为「未支持」。不会根据臆测坐标点击兵种。

`donation.py` 的离线执行器使用以下归一化观察契约；这是待实现的读取器接口，不是对当前游戏界面字段的已验证描述：

| 字段 | 所需证据 |
| --- | --- |
| `frame` | 必须等于当前截图路径；整体场景必须为高置信捐兵窗口 |
| `request_id` | 同一请求的稳定身份，防止窗口切换或他人请求替换 |
| `filled`, `capacity` | 当前选定类别的已填充及总容量 |
| `own_units` | 可归因于本账号对该请求的捐出数量；不能只用请求容量上涨代替 |
| `gems`, `elixir`, `dark_elixir` | 同一截图中可核验的货币库存 |
| `units` | 已识别单位列表：`id`、基准坐标 `bbox`、`space`、`currency`、`cost`、`allowed`、`enabled` |

只有允许且可用、容量足够、资源足够的圣水/黑油按钮可被选择；宝石按钮始终排除。每次只点一个单位，最多观察三张新图核验个人捐出数量、请求容量及资源支出，宝石必须不变。未核验的点击不重发，未知支出保留为 `null`。每次最多 50 次单位点击，仍受原任务与总运行期限约束。

这些观察字段是否能从实际界面可靠获得，必须在更新后采样验证。如果游戏不提供所需个人贡献证据，应根据实机可用证据调整读取器与验证契约，不能把缺失字段填成默认值以通过测试。`tests/test_donation.py` 全部使用明确的合成观察，不增加真实捐兵次数。

## 2026-09-24 制定的实测清单（历史记录）

1. 核对客户端版本、目标实例、分辨率与窗口布局，确认更新没有改变旧模板。
2. 在稳定亮屏条件下复测截图与游戏计时，定位之前的慢速问题。
3. 从界面执行一次真实村庄维护，验证日志、界面响应、停止和报告；再验证运行中关闭窗口。
4. 取得其他成员的真实可捐请求及选择窗口，接入并回放捐兵读取器，再做单次真实捐出核验。
5. 验证最新投兵与结算修复，完成一场完整自动战斗，然后按原标准完成连续 10 场、60 分钟组合运行和收益验收。
