## 状态与证据如何维护

- `PROGRESS.md` 页首维护当前状态和剩余工作；规划文件维护目标、依赖与退出条件；使用说明维护实际配置和代码契约。
- “代码已交付”“模型已训练”“离线已通过”“单场实机已通过”“连续验收已通过”分别记录。一次投兵或施法成功不能代替结算和回村证据。
- 历史验收记录保留日期、代码版本和原始失败结果。过去的“本次”“最新”“暂停”只属于该记录，不作为当前状态或新任务授权。
- `reports/`、`screenshots/`、`训练素材/`、`models/` 和 `datasets/` 是本地数据，不随 Git 发布；历史相对链接只在对应 checkout 保留了文件时可用。缺文件时保留“历史记录、原件待提供”的边界，不把链接或摘要当作本次复验。
- 实现或验收状态改变时，同一 PR 更新当前进度及受影响的计划/使用说明。纯文档整理检查链接、路径和事实一致性，不默认重跑全部产品测试。
