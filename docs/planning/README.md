## 执行顺序与待确认项

执行顺序为：固定试点 → 小批数据 → 建筑 B → 场景 S → 战术方案/旁路 → 单场与三场短实战 → 日常子批 → 连续验收 → R/U 战中增强。各批入口、退出、建议预算与状态统一维护在[分批实施计划](STAGED_IMPLEMENTATION_PLAN.md)，不在多篇文档重复更新。

本轮执行仅第 0 批和第 1 批试标部分。正式数据人工复核、真实捐兵机会、实际客户端/编队/视角、现场预算及 Jev 凭据可用性仍待对应批次核实；既有暂缓事项不因计划归档而解除。具备条件的正常授权采集可以保留动态素材，但不为此扩大当前批次或提前开启动态执行。

## 维护方式

实现阶段推进时，同一 PR 更新受影响的子计划和[当前进度](../PROGRESS.md)；执行模式改变同步主计划，模型包契约改变同步接口文档。数据、模型、代码、离线结果与实战分别记版本和状态。

文档改动至少检查 `git diff --check`、规划索引覆盖、本地链接/锚点、引用的代码路径和可运行命令。未随仓库发布的历史报告单列为本地证据，不要求新克隆伪造缺失产物，也不把文档检查通过当作产品验收。
