## 2. 必须采集的素材矩阵

表中的数量是首轮补采预算和覆盖检查起点，不是“达到数量就自动合格”。同图可服务多个任务，不相加成总图数；相邻帧不能充当独立阵型。正式测试所需的每类数量另受训练计划的准入要求约束。

正式验收可能需要超过首轮预算。例如训练计划要求大本营来自至少 100 个独立测试阵型，200–300 个总阵型按 70/15/15 拆分达不到；应在采集前预留这些测试组，并扩大总量或调整组级比例，不能等训练后才从训练阵型里凑测试图。

| 素材 | 必须覆盖的画面 | 标注内容 | 第一轮目标 |
| --- | --- | --- | --- |
| 战前稳定全图 | 核心居中/偏置/分成多块；密集/分散；不同入口；普通外圈建筑 | 全部纳入范围的建筑框、可见性、阵型组、镜头、核心参考 | 先用 50 个独立阵型试标；扩至约 200–300 个阵型、500–1000 张差异图 |
| 关键防御外观 | 所支持等级、可见模式、方向；相似建筑；被部分遮挡 | 类别、外观变体、模式、方向证据 | 正式训练中每个启用类别争取 ≥200 个实例、≥20 个独立阵型；验证/测试另留 |

| 前戏连续片段 | 下前戏单位、清边、接敌、目标倒下、走偏、停止前戏或转主力 | 目标身份、事件时间、英雄状态、目标状态、动作记录 | 首轮 20–30 个独立片段，主动保留失败；每个要训练的触发事件至少 30 次作原型 |

## 3. 标签定义

### 3.1 界面与覆盖层

先采用代码[场景定义](../../src/autococ/scene.py)中的稳定名称：`starting`、`village`、`training`、`search`、`enemy_village`、`battle`、`settlement`、`popup`、`disconnected`、`maintenance`。`training` 指游戏军队界面，和模型训练任务不同。

- “进攻菜单”不按目录自动映射为 `search`：逐图确认现有识别语义；无法对应时标 `unknown` 并记录 subtype。
- 断线/维护覆盖画面优先于背景场景；其他阻止操作的模态窗口标 `popup`。纯装饰提示不覆盖已知场景。云雾/转场仅在有足够搜敌依据时标 `search`，否则未知。
- 另存 `background_scene`、`overlay_type`、`reason`，允许后续扩展而不改原图。
- `unknown` 是数据集真值和拒识评估标签。当前分类器输出名单不允许 `unknown`；训练时不把未知图塞进普通 softmax 类，验证时用于调拒识阈值，测试时衡量误接受。
- 部落聊天、捐兵等第一轮不训练，先归拒识/范围外；若将来加入，要独立增加样本并映射现有 scene 名。

### 3.2 建筑类别与属性

建立版本化 `taxonomy.json`，下列英文名是本计划拟定的稳定标签名，不代表旧模板已支持。类别注册表与每次训练启用的子集分开；导出时生成连续的输出索引映射，不能通过目录排序猜 class ID。

| 标签组 | 先采、先标的对象 | 训练与使用规则 |
| --- | --- | --- |
| 基础关键目标 | 大本营 `town_hall`、部落城堡 `clan_castle`、防空火箭 `air_defense`、空气炮 `air_sweeper` | 作为通用候选；必须在选定版本/等级中实际存在且有足量样本才启用 |
| 核心防御 | 地狱之塔 `inferno_tower`、X 连弩 `x_bow`、投石炮 `scattershot`、巨石碑 `monolith`、法术塔 `spell_tower` | 每类单独统计，不能只报“防御”总准确率 |
| 其余可见防御 | 加农炮 `cannon`、箭塔 `archer_tower`、迫击炮 `mortar`、法师塔 `wizard_tower`、炸弹塔 `bomb_tower`、已显形特斯拉 `hidden_tesla` | 保留身份帮助威胁与路径分析；隐蔽未显形建筑不画猜测框 |
| 版本扩展 | 天鹰火炮 `eagle_artillery`、合并防御和当前版本新防御 | 按实际画面及游戏内名称核对后追加；不得假定它们在所有等级或版本同时存在 |
| 外围目标 | 储存器 `resource_storage`、采集器 `resource_collector`、经核对的其他非防御建筑 `other_building` | 第一轮可用这三个粗类保留几何；扩细类时保留历史 coarse 标签和映射 |

`other_building` 只表示已确认属于非防御建筑的对象，不能成为无法辨认防御的垃圾桶。城墙、装饰、树木、英雄、兵种、残骸和 UI 不混进此类。

属性单独标注，不通过大量复合类别膨胀检测头：`level`、`appearance_variant`、`mode`、`direction_image_deg`、`visibility`、`occlusion_fraction`。不确定即 `null`；空气炮方向只有能辨认时填写，图像角度约定右方为 0°、顺时针增加。模式/等级识别需另行评估，建筑框模型不会自动输出这些字段。

### 3.3 框、通路与核心参考

- 建筑 `bbox` 为原图像素 `x_min,y_min,x_max,y_max`，围住可见建筑主体与可辨认底座，排除血条、名字、攻击光束、阴影和范围圈。重叠目标逐个标；不按看不见的完整建筑尺寸脑补框。
- 可见主体不足约一半或类别不确定时，记为 `ignore/uncertain`，留原因。正式检测训练的导出器必须处理它：选择已完整标注的图/裁块，或实现并验证 ignore-aware loss；标准 YOLO 标签没有通用 ignore 框时，不能悄悄漏标后当背景。
- 可选 `ground_anchor`/`footprint_polygon` 独立表示底座落点和占地；视觉框中心不能直接充当寻路格点。标不了就留空。
- 墙体用折线/掩膜，隔间用多边形与邻接关系，部署区域用多边形；原图、ROI、模型输入、1280×720 基准之间保留变换。红线未显示时不把推测标成“可见真值”。
- 核心参考用 `core_regions[]`，允许 0/1/多个。每区记录成员建筑 ID、范围和依据；再记录 `strategy_profile_id`。不同打法可对同图有不同目标优先级，核心不是固定“一大框”。
- “从几点击入”“哪些目标先拆”“前戏成功条件”放入策略参考标签，供规则/Jev 旁路评估，不作为检测器输出事实。难以确定时允许多种可接受入口，不强造唯一答案。

### 3.4 战中事件与状态

| 任务 | 必留标签 | 未知边界 |
| --- | --- | --- |
| 建筑状态 | `track_id`、`visible_intact / visible_damaged / rubble_confirmed / occluded / out_of_view / unknown` | 一帧消失不标摧毁；需同一位置、稳定镜头与可见残骸/经复核的事件依据 |
| 英雄 | 身份、框、可见血条比例或 `high/mid/low`、技能 UI 状态 | 特效遮挡时血量未知；受击/濒死不能只由一个颜色猜测 |
| 主力 | 群体区域、分成几群、所属策略阶段、相对目标区的位置 | 群体中心不代表全部部队都已进入；无需给遮挡个体编造精确计数 |
| 卡片/技能 | `available / selected / depleted / unavailable / unknown`，身份、数量及来源分别存 | 卡片灰色、身份消失和数量零分别标，不能互相替代 |
| 时序 | 帧时间、目标事件发生区间、输入开始/结束、实际消耗证据时间 | 不知道精确发生时刻时用区间；视频剪辑跳转与暂停必须记录 |

每个关键事件同时保留发生前、发生中、发生后的图。前戏成功/失败、主力走正/走偏均采；错误案例按原因标，不能仅按星数把全部动作判对。

## 4. 采集方式与时序精度

1. 先整理现有 146 张，修复缺少的来源/标签/分组；取不到旧游戏版本时保留未知，作为开发辅助，不能进入某版本正式验收集。
2. 新静态样本在画面稳定后保留原生截图，记录分辨率、真实缩放、UI 布局、游戏版本与语言。原图保持无压字；标注叠图和缩略图另存。优先单一实际部署环境，其他环境作为范围外/扩展集合。
3. 新时序样本优先来自用户选定的手动战斗/可用回放与现有记录。先做每段 10–30 秒的受控采样，覆盖事件前后；不自动开战刷大量样本。
4. 时序原型争取 5–10 帧/秒，并逐帧记实际采样间隔、丢帧、取帧开始/结束时间；这是采集目标，需先测带宽与存储，达不到就保留实际速率。连续样本不能插进当前默认连续投放窗口破坏“零观察”约束，需独立采集模式/录像来源。
5. 以 10 秒有界环形缓存为起点，事件触发保存前 3 秒、后 5 秒，重叠窗口合并。采样任务显式限定场次、时长和磁盘额度；满额停止新增保存，不删除旧证据。缓存压缩在非实时路径执行。
6. 新的 `capture_started_monotonic` 只在其本次进程/会话内可比较；另记 `session_clock_id`、UTC 时间与视频相对时间。历史 observation 时间不得改名冒充取帧起点。
7. 教程视频用于提取规则及补充困难示例。记录作者、URL、时间点、画面裁剪和暂停/倍速；水印、字幕、剪辑、缩放与本机不同，单列 `source_domain=tutorial`，不混入本机最终验收。此计划不依赖再次下载任何特定视频。

## 6. 标注复核、去重和拆分

1. **试标**：从不同目录抽 50 张、至少 10 个阵型，制作类别正反例和易混淆表。先解决弹窗优先级、框边界、ignore 和模式标签，再批量标。
2. **预标注**：现有识别或新模型可提建议，全部保持 `pending`；人工确认后才进入正式标签。每张检测训练图对启用类别完整标注，不能只画核心建筑却把同类外围目标漏掉。
3. **质检**：验证坐标、类别、源哈希、派生映射、重复 ID、状态矛盾。训练图至少抽 10% 二次复核；关键稀有类、ignore、全部验证/测试真值逐项复核，测试标注冲突在封存前解决。
4. **分组**：按文件/像素哈希、近似图、同一阵型、同战斗、连续片段、派生裁图建立关联图；连接分量形成 `leakage_group_id`。界面无阵型时用会话/UI 状态变体约束。同阵型跨会话仍同组；逐组检查既有 `tests/fixtures` 与 `assets` 重合。
5. **拆分**：默认组级 70/15/15，固定种子 42；类别覆盖不够时补采或调整组数，不能把组拆开凑比例。产生跨组重复/训练与测试重叠时校验失败。没有足量独立测试组则报告数据不足。
6. **冻结**：验证集供阈值与模型选择；测试集在标签、支持范围和准入门槛冻结后开启一次。用测试失败样例再训练后，原测试集降为回归集，并新建独立验收集；保留版本关系。

## 7. 交付顺序与完成条件

| 阶段 | 实施任务 | 可检查的产物 |
| --- | --- | --- |
| D0 盘点 | 只读导入旧清单，统计类别/阵型/版本/标注缺口 | 146 张旧 ID 对应表、缺口报告、无原件变更证明 |
| D1 规范 | 实现清单/标签 schema、试标、稳定 taxonomy 与导出映射 | 50 张试标、示例叠图、标签指南、自动校验报告 |
| D2 静态补采 | 按第 2 节采集正常/异常界面和战前阵型 | 每类实例数、独立阵型数、版本与外观覆盖表 |
| D3 动态素材 | 随 D2 同步收前戏与主力片段，补时间和动作依据 | 事件索引、有效帧率、成功/失败分布；不宣称实时能力已接入 |
| D4 冻结与交接 | 完成复核、泄漏检查、组级拆分、可移植快照 | 数据版本/哈希、训练/验证/测试组清单、DATASET_CARD、未满足项 |

进入正式模型实验的必要条件：标签规则稳定、启用类别完整标注、分组无泄漏、来源可追溯、训练与验证覆盖达标。数据不足时可以做管线冒烟，但必须标 `prototype_only`。材料目录整理完成与数据集可训练分别记录。

Windows 开发/采集/测试遵守[主计划临时保活流程](VISION_AGENT_PLAN.md#101-windows-临时防息屏与防睡眠流程)。跨机交接只传用户选定的素材快照、标签和哈希，不传本机凭据、配置或整个 reports 目录。原图、训练快照和模型各有独立版本，移动后核对 SHA-256；本地备份不能只依赖 Git。

## 8. 现在可推进与实施时才需补齐的信息

现在可以实现 D0/D1 的通用工具并试标已有图。首套配兵、支持的游戏版本/大本营范围决定最终启用类别和补采覆盖；正式冻结时把这些值写入 dataset card，未知时只停在相应验收门，不阻塞清单和标注工具。任何依赖特定前戏的策略都必须明确自己的目标类别与触发事件。

当前 146 张只能作为启动材料。没有正式标注、独立阵型计数和版本信息时，不推断它们足够训练，也不把旧素材目录说明中的“动态以后再采”沿用为本次目标：本次要求动态素材从第一轮开始积累。
