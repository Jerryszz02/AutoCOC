# 日常助手交付与实机证据

本页对应 `agent/daily-assistant` 的新增功能。现有完整验收门槛继续见 [ACCEPTANCE.md](ACCEPTANCE.md)，使用方式见 [DAILY_ASSISTANT.md](DAILY_ASSISTANT.md)。离线测试、截图回放、界面显示和实际游戏结果分别记录。

## 实施状态

| 阶段 | 当前交付 | 尚未完成 |
| --- | --- | --- |
| 1. 任务、界面与资源筛选 | 独立任务、两页界面、统一校验与筛选、计数接线已实现 | 连续使用验收见阶段 4 |
| 2. 识别、配兵与打法 | 77 项单位目录、13 种本版头像样本、配兵执行器与 TOML 动作计划已实现；纯法术提前结束已实测一场 | 全单位识别素材、当前保存／编辑页完整观察、真实自动修改配兵尚未打通 |

| 4. 连续运行 | 兼容迁移、异常分类、停止与回执已实现 | 连续 10 场及 60 分钟组合运行尚未验收通过 |

因此本次是可检查的阶段性交付，不能视为全部四阶段完成。

## 已接通的执行路径

- Tk「运行／配置」页面、可排序的任务勾选、独立任务参数和同类多任务持久化；CLI、GUI、TOML 使用相同定义与校验。
- 任务执行前读取目标，战后结算回村后再核对；分别累计完成战斗、胜利、目标达成和可核验收益。已结算回村但部分动作失败的战斗仍如实计数，任务失败继续保留并停止。
- 资源筛选采用启用条件同时满足，未知金额不当零；到搜索上限后退出搜敌并确认回村，不降低门槛。
- TOML 有序动作、独立英雄技能回执、法术消耗核对、目标建筑状态及有条件提前结束；本地 Python 扩展只接收上下文并生成动作表。
- 单位稳定 ID 与客户端样本目录分开管理；建筑识别需要经过独立样本校验的模板。缺素材的功能会显示未支持。
- 回村弹窗、协作停止、总时限、单步时限与动作不确定时停止；不会盲目重放输入。

这些路径通过测试并不代表所有兵种、活动、建筑外观或真实游戏场景已经验收。

## 仍需取得的证据

1. 修复后同一交付版本连续 10 场完整实战，以及至少 60 分钟组合运行；失败窗口独立保留，不拼接计数。
2. 自动配兵需要完整确认所保留的军队、英雄、攻城器、宠物与装备，并验证切换后的实际数量。只有部分身份样本时不能应用整套已存配置。
3. 当前活动的得分规则、入口与真实进度；示例适配器不是已经校准的活动。
4. 已接受的防空火箭或法术工厂任务，以及稳定视角下建筑存活、受击和真正摧毁的独立样本。建筑消失或烟雾遮挡不能算摧毁。
5. 其他单位、滚动与灰卡等状态按客户端版本逐项补齐独立样本。`capabilities` 的 `sampled` 表示样本存在，不表示全兵种已验收。

捐兵入口保留，目前仍缺真实捐兵窗口校准。扫描范围内未发现请求可报告该范围无机会；找到请求后无法识别捐兵窗口时必须报告未支持，不能报告捐兵成功。本轮无请求的扫描结果不代表捐兵已可用。
