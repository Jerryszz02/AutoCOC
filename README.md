# AutoCOC

公开仓库包含源码、测试、识别模板和文档；本机配置 `config.toml`、虚拟环境、运行报告 `reports/` 与截图 `screenshots/` 不随仓库发布。下文及文档中的历史报告链接仅在保留对应本地数据时可用；依赖这些原图的回放测试在缺少样本时会跳过。首次使用请按安装步骤从 `config.example.toml` 创建本机配置。

AutoCOC 是 Windows + MuMu 上的本地《部落冲突》自动化项目，通过 ADB 或可选的 MuMu 原生 SDK 截图和模拟输入运行任务。当前正在重构、迭代和现场验证，**完整自动对战、资源收集、部落捐兵、请求增援的组合目标尚未通过完整验收**。单元测试、截图回放和某一次任务成功都不能替代持续现场验收。

量化目标、成功定义和证据要求见 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。初始收益目标包括金币与圣水战斗毛收益合计至少 2,000,000 / 小时、扣除已核验经营支出后的净产出至少 1,000,000 / 小时；这些是目标，不是当前已取得的成绩。

## 当前实现与边界

- 设备层严格优先使用指定 serial；显式指定的设备不可用时不会切到其他设备。自动发现多个就绪目标时要求指定 serial，不按列表顺序选择。ADB 和动作调用有超时。
- MuMu 多显示器分别绑定截图的物理 ID 和输入的逻辑 ID。运行启动后会重新定位游戏实际所在显示器，避免截错屏或点错屏。
- 可选 MuMu 原生传输核对实例、ADB 端口、版本及游戏显示器；SDK 在独立进程中运行，超时终止工作进程，不重放输入或自动切换通道。截图、点击、滑动和返回已接入，文字输入仍走绑定显示器的 ADB。接口返回成功不代表游戏动作已生效。
- 冷启动时，ADB 的显示器可能先于 SDK 和首帧就绪；首次连接会在启动/会话期限内重新解析显示器并等待首帧，保留原始错误码。错误实例和其他故障不重试；运行中的截图或输入故障仍停止，不重新投放动作。
- “因为太久没有进行操作，您已断开连接／重新载入游戏”优先识别为断线，不采用背景村庄按钮证明启动成功；实际恢复仍可能卡在启动画面并超时。
- 目标游戏已在前台时复用当前进程，其他前台状态仍发送启动指令；连接事件记录是否启动。后续仍须截图确认村庄，前台包名本身不算启动成功。
- 本地 RapidOCR 识别中文/英文文本与数字，OpenCV 匹配截图模板。未知、低置信度、过期或非当前截图不能用于执行点击。
- 任务调度分别记录 `succeeded`、`failed`、`skipped`、`simulated`，按任务结果核验；成功轮次数与成功任务数分开。
- 资源收集、军队/对战和部落交互由各自的任务模块实现，现场适配和验证持续进行。当前模板与识别规则源自本机中文画面，不代表所有语言、账号布局、兵种和模式都已支持。
- 战前从军队页面独立检测卡片和数量，再与战斗栏核对自身部队及法术；带明确援军标记的额外数量卡单独纳入计划。结束前逐卡确认耗尽；灰卡裁剪保留字符宽度和位置变化余量，仍要求明确 `xN` 且置信度至少 0.9。
- 已接入英雄血条、大守护者及所采样蛮王、亡灵王子、弓箭女皇的技能就绪/使用后状态，以及攻城器部署验证。后三位已有单次技能点击的受控实机样本与离线回归，仍需正式完整对战验证。技能点击最多一次，动画只重拍；未观察的装备和外观仍不支持。仅数量卡耗尽会记录 `numeric_completed`，完整 `completed` 还要求计划内支援和英雄技能验证。
- 一批落兵点击必须核对全部已发出点击的数量消耗，第一次看到减少可能只是中间帧；最多观察三张新图，未完整确认就停止，保留已验证的部分数量。
- 部分投放失败且仍能识别战斗时，继续收集结算并回营，保留失败；不盲目重投。结算数字不全时最多补拍 3 帧、受 10 秒窗口和任务期限限制，不能倒推未知奖励。
- 胜利结算支持观察到的三行战利品及右侧独立奖励面板；奖励须有标签、资源图标和明确正号数字。星数按完整五角星轮廓识别，一星有真实原图回放，二/三星仅有合成图测试；缺失或冲突仍为未知。大守护者金书就绪模板补充实际发光动画相位，仍要求装备、卡片与血条共同验证。
- 外侧短边界可否决阵内落兵候选，选中卡薄白边和背景相连的攻城器标题栏已有回归。搜敌字段不全先重读，OCR 大小写和缺失字段恢复不算换敌证据；同帧已验证的卡片消费结果可复用，新截图仍须重读。
- 搜敌等待上限为 60 秒，仍受任务总期限限制。 敌方资源可读后，还须云层消散及相邻截图确认镜头稳定，再读取最新资源并选敌；云层下读到文字不算可执行画面。卡片短暂漏检最多补两张新图，不重复落兵。平移优先采用新图中的空草地起点及 1,200 ms 时长。平移后没有边界时，用地图特征核对位移；只有确认未移动才补一次 1,200 ms 平移。边界仍不可读时允许至多 3 个明确空草地候选逐个单兵试探，只有兵数确实减少才继续部署；草地外观不代表已验证可落兵，花纹石地等无候选时停止。
- 结算行 OCR 漏读时，可按资源图标左侧的实际白色字符收紧裁剪，再要求高置信数字；空白、字母、冲突或位置错误不作零值。已有金币零值原图回放，原失败任务不追溯改写。
- 黑油结算图标、宠物角标和攻城器释放图标只比较不透明内容，避免地图背景污染模板；选中动画覆盖中间缩放和缩小卡框，仍要求独立完整边框。黑油修复已实机对账，其余最新支援修复仍待实机验证。部署复用刚取得的有效截图，动作后验证和时效检查保留。
- 已提供本地 Tk 桌面界面：任务勾选、运行参数、离线预演、实机执行入口、停止、日志、报告与截图预览。默认离线，打开界面不连接模拟器。旧规则骨架、训练成本参数等兼容字段不代表已有相应游戏策略。
- 捐兵新增请求窗口采样及逐单位核验执行器；生产识别器尚缺真实窗口读取器，所以当前实机路径会在打开请求后明确报告 `donation_layout_unverified`，不会点击未校准的兵种按钮。合成观察测试不代表真实捐兵已经完成。

## 图形界面

双击根目录的 [启动AutoCOC.cmd](启动AutoCOC.cmd)，或在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m autococ.gui --config config.toml
```

界面默认“离线预演”。选择任务组合、轮次、时长、资源门槛后即可查看计划和报告；游戏可测试时再手动选择“实机执行”。保存界面方案不会改写基础 TOML 或模拟器设置。完整操作说明与实测清单见 [docs/DESKTOP.md](docs/DESKTOP.md)。

## 安装

要求 Windows、运行中的 MuMu、可用 ADB，以及 Python 3.12 或更新版本。请在仓库根目录执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[image,dev]"
if (-not (Test-Path -LiteralPath config.toml)) { Copy-Item -LiteralPath config.example.toml -Destination config.toml }
```

RapidOCR、ONNX Runtime 和 OpenCV 已列在项目主依赖中，安装项目会一并安装本地识别依赖。OCR 使用 RapidOCR 包内的 ONNX 模型，推理不调用云端服务，也不在推理时自动下载缺失模型。模型文件缺失会明确报错；安装依赖本身需要能够访问相应软件包。

已有虚拟环境可直接使用，不必重复创建。

## 配置

编辑本地 `config.toml`，参考 [config.example.toml](config.example.toml)。至少核对：

- `adb.adb_path`：你实际 MuMu 安装目录中的 ADB 可执行文件。示例路径不是所有电脑通用的默认安装路径。
- `adb.manual_serial`：填写已确认的目标；当前本机 MuMu 实例 1 的管理器端口为 `127.0.0.1:16416`，已写入本地配置。其他电脑须重新确认，留空时仅在一个就绪目标下自动选择。
- 可选 `[mumu]`：填写绝对路径 `install_dir` 和明确的 `instance_index`，管理器须至少 6.3.2.0，当前支持 Android 12/15 引擎。本机已启用；删除整个该节可在下次新运行中使用 ADB。配置校验失败会停止，不在一次输入结果不明时切换通道补点。
- `game.package_name`：实际客户端包名；需要时设置 `launch_activity`。
- `game.display_id`：省略表示根据目标游戏所在屏幕自动解析；手动填写的是 Android **逻辑显示器 ID**，不是截图使用的长物理 ID。MuMu 可能在启动后将游戏移到另一个显示器。
- `runtime.step_timeout_sec`、`task_timeout_sec`：单条调用和单个任务的时间上限；`poll_interval_sec` 是等待画面变化的观察间隔。
- `stop.max_runs`：完整 Profile 的最大轮次；`max_duration_sec` 是运行时间上限。`--once` 临时将轮次设为 1，不改配置文件。

基准坐标为 `1280 × 720`；实际截图可缩放换算，但额外分辨率仍需独立验证。现有现场样本使用中文界面。

默认任务组合：

| Profile | 顺序 |
| --- | --- |
| `core-loop` | 启动 → 收集 → 请求增援 → 捐兵 → 对战 |
| `village-only` | 启动 → 收集 → 请求增援 → 捐兵 |
| `battle-only` | 启动 → 对战 |
| `social-only` | 启动 → 请求增援 → 捐兵 |

对战任务自行负责结算和回村，旧配置中的独立 `settle` 任务会明确报错。迁移旧配置时请同步更新 Profile。未启用的任务不会由调度器调用；执行失败会结束本轮并保留失败记录。

## 常用命令

以下命令均可从仓库根目录运行，不必激活虚拟环境。

检查设备、游戏所在显示器，并保存带唯一文件名的截图：

```powershell
.\.venv\Scripts\python.exe -m autococ.cli check --config config.toml
.\.venv\Scripts\python.exe -m autococ.cli capture --config config.toml
```

这两个命令不会启动游戏或发送游戏点击。游戏尚未运行或无法定位显示器时，会明确失败。截图与输入不再依赖 Android 的不稳定默认屏；截图命令也不再把默认屏的 UI XML 当作游戏识别依据。

离线识别一张已有截图，或识别当前游戏画面；标准输出是 JSON：

```powershell
.\.venv\Scripts\python.exe -m autococ.cli inspect --config config.toml --image .\screenshots\current.png
.\.venv\Scripts\python.exe -m autococ.cli inspect --config config.toml
```

`--image` 完全不连接模拟器；不带 `--image` 会先定位游戏显示器并保存新截图，但不启动游戏、不点击。JSON 包含 `scene`、`confidence`、截图路径和 `observations`；现场检查额外包含 serial 及逻辑/物理显示器 ID。日志写到标准错误和本地日志文件，不混入 JSON。输出 `unknown` 是诊断结果，不表示游戏任务完成。

先查看任务计划，再执行一个完整 Profile 轮次：

```powershell
.\.venv\Scripts\python.exe -m autococ.cli run --config config.toml --profile core-loop --dry-run
.\.venv\Scripts\python.exe -m autococ.cli run --config config.toml --profile village-only --once
.\.venv\Scripts\python.exe -m autococ.cli run --config config.toml --profile battle-only --once
```

不带 `--once` 按配置轮次与时限运行。`--dry-run` 只产生 `simulated` 结果，不连接游戏，真实成功数和真实收益均不会增加。旧 `sample` 命令仅作为单张截图命令的弃用别名，不再冒充游戏成功。

运行退出码：有明确成功或正常跳过、且没有失败时为 `0`；显式模拟运行完成也为 `0`。任务失败、初始化失败、缺少任何可核验结果为非零；用户中断为 `130`。参数错误由命令行解析器返回 `2`。可在 PowerShell 用 `$LASTEXITCODE` 检查。

## 报告与证据

每次运行使用包含微秒与随机后缀的 `run_id`。产物包括：

```text
reports/run-<run_id>.md       # 人可读摘要
reports/run-<run_id>.json     # 同一运行的机器可读结果
reports/<run_id>/events.jsonl
reports/<run_id>/frames/     # 带序号的观察与验证截图
```

报告记录模式、Profile 轮次、任务尝试/成功/失败/跳过/模拟数、停止原因、任务证据和资源账本。金币、圣水、黑油分开，战利品、战斗奖励、收集入库、捐兵支出和搜索支出分别核算；按整个运行墙钟时间计算每小时指标。未识别金额为 `null`/`unknown`，不会用零代替；证据不足时不能据此宣称收益目标已经达成。

`provenance` 保存启动时磁盘源码与模板清单的 SHA-256 指纹，以及应用 CLI 覆盖后的生效配置哈希；配置值不会完整写入报告。这些字段用于比对运行版本，不是已加载模块字节码证明。未识别的客户端版本保留 `unknown`。

截图优先读取已支持的 RAW RGBA 格式，在本机编码为 PNG；格式不支持时按剩余超时预算回退设备 PNG。证据文件仍为 PNG，观察事件记录 `capture_method` 和 `capture_elapsed_sec`，便于核查采集开销；单次截图速度不代表整轮性能保证。

`reporting.save_decision_trace=false` 会从 Markdown 与 JSON 中移除决策轨迹。截图和报告不会使用旧的 `start.png`、`done.png`、`current.png` 固定名字覆盖历史证据。

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

单元测试使用模拟 ADB、离线图像或受控任务收据，不会代替真实游戏验收。完整交付仍需逐项满足验收文档中的持续对战、收集、捐兵、请求、资源收益和故障恢复门槛。
